Future Work

SOP Lang is still under development and may undergo significant changes as it becomes more tightly integrated into the workspace. It was previously integrated into a prototype based on an older architecture, and due to new insights and the emergence of Ploinky, this integration needs to be redone and leveraged by agents that specifically require such capabilities.

Current Assessment

Initially, the expectation was that all agents would benefit from this approach, and this may still be true in part, but SOP Lang has proven to be quite heavyweight. In some scenarios, using custom code, whether AI-generated or manually written, is preferable.

The agent architecture described through AchillesAgentLib can serve as a pragmatic alternative in specific contexts. It offers simple primitives for adding skills to agents as custom code, enabling quick delivery without depending on SOP Lang in every workflow.

For other situations, agents may still be better described in a language like SOP Lang, because each team could customise behaviour safely without touching core JavaScript or Python runtime code.

Likely Directions

  • Refinement of macro and dependency semantics where undefined values complicate change detection and update signalling.
  • A faster runtime variant oriented toward short-lived executions rather than long-running persistent flows.
  • Stronger integration with containerised Ploinky agents, likely by exposing orchestration methods through AchillesAgentLib.
  • Further clarification of context-management models for complex conversations and collaborative assistants.
