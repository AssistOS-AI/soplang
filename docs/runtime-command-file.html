file

file tracks filesystem state of a path and returns stat metadata (mtimeMs, ctimeMs). It is used as reactive trigger for pipelines depending on file changes.

Syntax

@fileState file "/absolute/or/relative/path.txt"

Example

@content file "/tmp/inputA.txt"

# later, command is replaced:
@content file "/tmp/inputB.txt"

Validated in tests/pipelines/basic/fileCommandTest.mjs. The test checks that variable clock remains stable if file is unchanged and advances when stat metadata changes.

Step-by-Step Interaction

The runtime resolves the file path either relative to the document source path, when that context exists, or relative to the current working directory otherwise. After path resolution, the command reads filesystem stat metadata and extracts the mtimeMs and ctimeMs pair used as reactive signal. When those values change, the runtime updates the output variable and invalidates dependents that rely on this file state. When the values remain unchanged, the runtime keeps the previous object to avoid unnecessary graph recomputation.

Runtime Behavior Notes

The command expects exactly one non-empty string argument, and the runtime records an error if that contract is not respected. Relative paths are resolved deterministically according to document path first and process directory second. Stable stat metadata leads to value reuse by design, while stat failures produce undefined outputs accompanied by explicit error information. This behavior makes the command safe as both a file watcher trigger and a build dependency anchor.
