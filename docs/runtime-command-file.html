files / glob

files (alias glob) resolves a Unix glob pattern and returns an array of file metadata objects (path, mtimeMs, ctimeMs). It is used as reactive trigger for pipelines depending on file set and content changes.

Syntax

@matches files "./data/**/*.txt"
@sameResult glob "/tmp/logs/*.{txt,log}"

Example

@topLevel files "./fixtures/*.txt"
@recursive glob "./fixtures/**/*.txt"

# later, pattern is replaced:
@topLevel files "./fixtures/nested/*.txt"

Validated in tests/pipelines/basic/filesCommandTest.mjs. The test covers both files and glob, using different patterns (*, **, ?, brace expansion) and checking clock behavior when matches change.

Step-by-Step Interaction

The runtime resolves the glob pattern either relative to the document source path, when that context exists, or relative to the current working directory otherwise. It then expands matches and reads stat metadata for every matched file, producing a sorted array of objects with path, mtimeMs, and ctimeMs. When file metadata or the matched set changes, dependent variables are invalidated and recomputed.

Runtime Behavior Notes

The command expects exactly one non-empty string argument (Unix glob pattern), and the runtime records an error if that contract is not respected. Relative patterns are resolved deterministically according to document path first and process directory second. Stable metadata leads to value reuse by design, while filesystem failures produce undefined outputs accompanied by explicit error information. This behavior makes the command safe as both a watcher trigger and a build dependency anchor.
